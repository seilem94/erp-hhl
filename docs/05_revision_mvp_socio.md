# Guía de validación con el socio

Responsabilidad: recoger decisiones de uso y criterios de aceptación del producto. No es un inventario de funciones entregadas; consultar [PROJECT_STATE.md](PROJECT_STATE.md) antes de preparar la demostración.

## Preguntas de la reunión

| Área | Preguntas por resolver |
| :--- | :--- |
| Alta de obras | ¿Qué datos son imprescindibles al comenzar? ¿Dirección, contacto, alcance u otros? |
| Seguimiento | ¿Qué información debe aparecer primero en el teléfono? ¿Qué estados y filtros resultan útiles? |
| Registro de gastos | ¿Qué categorías utiliza el equipo? ¿Qué campos pueden completarse después? |
| Comprobantes | ¿Cómo se justifican gastos sin boleta? ¿Cuándo se necesita cámara o carga de un archivo? |
| Imputación | ¿Cómo se distribuye una compra entre varias obras? |
| Gastos generales | ¿Qué costos corresponden a la empresa y no a una obra concreta? |
| Reportes | ¿Qué período y agrupación necesita el socio para revisar gastos? |
| Conectividad | ¿Qué tareas deben poder continuar sin señal y cómo resolver registros duplicados? |

## Medición de experiencia

Probar el registro de un gasto representativo con usuarios reales. La meta inicial de veinte segundos es una hipótesis de UX, no un resultado medido. Registrar dispositivo, condiciones de red, tiempo, errores y observaciones.

## Acuerdos

| Fecha | Decisión del usuario | Criterio observable | Responsable |
| :--- | :--- | :--- | :--- |
| Por completar | Por completar | Por completar | Por completar |

No transformar preguntas pendientes en requisitos aceptados ni en afirmaciones de capacidad actual.
